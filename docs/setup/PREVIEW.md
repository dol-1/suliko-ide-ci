# D-058 setup preview (not an installer)

This is a security-first **preflight only** for official BB [desktop-v0.49.0](https://github.com/get-bb/bb/releases/tag/desktop-v0.49.0). It does **not** run downloaded installers, configure providers, install Suliko plugins, modify BB user data, or create privileged accounts. No release or beta readiness is claimed.

On macOS Apple Silicon or Linux x86_64 use `bash scripts/suliko-setup.sh --dry-run`, `--download-verified` (network + official SHA-256 validation only), or `--uninstall` (only Suliko-managed download cache). The Bash preview refuses to overwrite a same-named existing download. It creates a local ownership marker only after checksum verification; uninstall requires the matching marker **and** revalidated asset digest, leaving untracked, forged-marker or changed files untouched. A crash may leave an untracked cache file requiring manual inspection; cleanup is deliberately conservative. On Windows x64 use `pwsh -File scripts/suliko-setup.ps1 -DryRun`, `-DownloadVerified`, or `-Uninstall`. Neither script silently invokes an executable or installs services. All modes run as current user, no sudo/admin.

Official BB README warns Windows and Linux desktop packages are **alpha**, native Windows requires Git for Windows, and Intel macOS uses the `npx bb-app` alternative; unsupported platforms fail closed here. The checksums are pinned to the asset digest data in the official release API. Checksums alone are not proof of publisher identity or code-signing verification.

The public CI preflight checks dry-run behavior, wrong-checksum rejection, official HTTPS asset SHA-256 verification **without executing the asset**, and tracked cache cleanup. An exact-head completed green CI run is required as evidence; code alone is not proof. This is **not** installation success. Remaining E1 gates: unattended user-level installation, SEC-02 on a live installed instance, plugin marketplace, clean uninstall, three-platform evidence and total time under 15 minutes. Never run scripts from untrusted third-party URLs.

**D-090 Windows official EXE trust caveat (2026-11-13):** The upstream desktop-v0.49.0 official asset matches release SHA256, but actual hosted Windows `Get-AuthenticodeSignature` returned `NotSigned`. Upstream README documents Windows binaries can be unsigned absent `WIN_CSC_LINK` and `WIN_CSC_KEY_PASSWORD`. SHA256 match alone is not code-signing provenance. The standalone D090 diagnostic only checks pinned digest and reports fixed status; signed-execution D084 remains fail-closed. No SmartScreen bypass, Windows install success, owner machine or beta GO is implied. Decision on an unsigned trust policy requires independent Claude review. See Suliko IDE #42/#62.
