# SEC-03 — packaged Electron sender/frame negative probes

**Staging only, 0/5 executed.** Uses Playwright `_electron` and a test-owned synthetic foreign `BrowserWindow` with an IPC-capable preload to test **BB core's sender authorization**, without modifying stock BB itself. Test requires disposable, reviewed Electron 0.49.0 packaged binary at `BB_SEC03_ELECTRON_BINARY` and Linux Xvfb. All five cases fail closed on missing setup, no skip/retry/allow_failure.

Source: pinned [BB main IPC](https://github.com/get-bb/bb/blob/desktop-v0.49.0/apps/desktop/src/main.ts), [browser main IPC](https://github.com/get-bb/bb/blob/desktop-v0.49.0/apps/desktop/src/desktop-browser-main-ipc.ts), [server-choice IPC](https://github.com/get-bb/bb/blob/desktop-v0.49.0/apps/desktop/src/server-choice-ipc.ts), [clipboard](https://github.com/get-bb/bb/blob/desktop-v0.49.0/apps/desktop/src/desktop-clipboard.ts), [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), [IDE issue #21](https://gitlab.com/dol-1-group/suliko-ide/-/work_items/21), Memo D-031.

Case IPC-01 is a **source-supported hypothesis** that `get-info` currently allows unapproved senders, not a confirmed exploitable vulnerability. IPC-04 requires a schema-valid synthetic request; a returned tab-not-found alone is not strong proof of sender authorization. Tests are designed to reveal regression or deviations; if a test fails, first validate fixture/harness and origin model in real packaged context. Do not automatically call a failed assertion a security exploit. For *confirmed* exposure, open `audit::finding` and prepare (do NOT send) an upstream disclosure draft per upstream SECURITY.md. Never publish exploit payloads, real session data or production tokens.

**Run only on sandboxed CI:** `cd tests/sec03 && npm install --no-audit --no-fund && BB_SEC03_ELECTRON_BINARY=/reviewed/packaged/electron xvfb-run -a npm test`. Requires SHA-verified stock BB SPIKE-02 packaging; no GUI test has run.
