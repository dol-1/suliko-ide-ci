# მომავალი პილოტი: პირველი 15 წუთი (ჯერ არ გახსნილა)

**ეს მხოლოდ წინასწარი, პირობითი გზამკვლევია. Suliko IDE პირად ან საწარმოო კომპიუტერზე ახლა არ დააყენოთ.** 15 წუთი სასურველი სამიზნეა და არა გაზომილი შედეგი ან მოწვევა. რეალური პილოტისთვის საჭიროა ცალკე უსაფრთხოების და owner-ის GO. Windows-ის BB-ის ოფიციალური ინსტალერი **NotSigned**-ია; უსაფრთხოების გაფრთხილებას გვერდი არ აურიოთ. BB-ის CLI Windows-ზე მხოლოდ **Ubuntu WSL2**-ში მუშაობს; GUI ნატიურია. **Remote** არის სინთეტიკური **mock** და არა ცოცხალი სერვისი.

## მხოლოდ დამტკიცებული, ნებაყოფლობითი პილოტის სესია

1. **0–3 წუთი — დაშვება და წინაპირობები.** გადაამოწმეთ, რომ პილოტი ნამდვილად გაიხსნა, BB 0.49.0 ოფიციალური პაკეტი და Suliko-ს უცვლელი კანდიდატი შემოწმებული SHA-256-ითაა. ჰეში ფაილის ბაიტებს ადასტურებს და არა გამომცემლის ხელმოწერას. ნებართვის არქონისას აქ შეჩერდით.
2. **3–8 წუთი — დაყენება მხოლოდ დამტკიცებულ იზოლირებულ გარემოში.** გამოიყენეთ თქვენი სისტემისთვის ცალკე დამტკიცებული და ვერსიაზე მიბმული ერთბრძანებიანი ინსტალაცია; არ ჩამოტვირთოთ თვითნებური სკრიპტი. [ინსტალაციის განმარტებაში](install.ka.md) აღწერილია Windows GUI/WSL2 და უსაფრთხო წაშლის საზღვრები. არ გახსნათ ინტერნეტისთვის პორტი და არ გამორთოთ დაცვა.
3. **8–11 წუთი — Hello-ს პირველი დავალება.** მხოლოდ საჯარო ან სინთეტიკურ პროექტში გახსენით **Suliko Hello** და ჩაინიშნეთ: პანელი გამოჩნდა? უვნებელი საცდელი მოქმედება შესრულდა? (დიახ/არა/უცნობია). არ გამოიყენოთ გასაღებები, პირადი პროექტები, screenshot ან ლოგი.
4. **11–13 წუთი — Doctor დამტკიცებული pilot build-ის შემთხვევაში.** უფლებამოსილ შემმოწმებელს შეუძლია ადრე დადასტურებულ, საკუთარი მომხმარებლის იზოლირებულ BB 0.49.0-ში გაუშვას `node scripts/suliko-doctor.mjs --live --bundle NEWFILE.json`. ეს მხოლოდ კითხულობს მონაცემებს, ამოწმებს loopback-ს და ნებადართულ plugin-სტატუსებს და JSON ანგარიშს ქმნის **ახალ ფაილში**. წარუმატებელი live ტესტი არ ითვლება მწვანედ; `--fixture` სინთეტიკურია. გარემოს ცვლადის სახელის არსებობა ნამდვილ გასაღებს არ ადასტურებს.
5. **13–15 წუთი — ნებაყოფლობითი პასუხი და უსაფრთხო დასრულება.** გამოიყენეთ [კონფიდენციალური უკუკავშირის შაბლონი](pilot-feedback.ka.md). მიუთითეთ მხოლოდ ზოგადი შედეგი და, სურვილისამებრ, დროის მიახლოებითი კატეგორია. თუ საჭიროა, წაშალეთ მხოლოდ საკუთარი, დამტკიცებული ინსტალაცია; სხვის BB-ს ნუ შეეხებით.

## Doctor-ის bundle-ის მიმაგრების წესი

**არ ატვირთოთ doctor-ის ფაილი საჯარო GitHub issue-ში.** უფლებამოსილმა მიმომხილველმა ჯერ უნდა შეამოწმოს JSON-ის ფიქსირებული სქემა, პირადი მონაცემები, გზები და გასაღებები. მიმაგრება დასაშვებია მხოლოდ იმ შემთხვევაში, თუ ცალკე დამტკიცებული **კერძო მხარდაჭერის არხი** გაიხსნა და ანგარიში სანიტიზებულია. ამ წინასწარ დოკუმენტში ასეთი არხი არ არის. სხვა შემთხვევაში აღწერეთ მხოლოდ ზოგადი კატეგორია; ვერ დადასტურებული live დიაგნოსტიკა მონიშნეთ `review-required`-ით და არ გააზიაროთ ნედლი მონაცემები.
